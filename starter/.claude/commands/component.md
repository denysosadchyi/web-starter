Створи новий компонент із іменем `$ARGUMENTS`. Слідуй конвенції проекту.

## Що зробити

1. Створи файл `assets/css/components/$ARGUMENTS.css` за template-ом нижче.
2. Додай `<link rel="stylesheet" href="assets/css/components/$ARGUMENTS.css">` у `<head>` `index.html` поруч із сусідніми `components/*` лінками.
3. Якщо компонент має HTML-приклад використання, додай мінімальний приклад у `index.html` всередині відповідної секції.
4. Якщо потрібна інтерактивність, додай нову пронумеровану секцію в `assets/js/main.js`.

## Template файлу

```css
/* ==========================================================================
   $ARGUMENTS.css — <короткий опис>
   Markup: <очікуваний HTML-кістяк, скорочено>
   Notes:  <будь-які неочевидні залежності або dark-bg overrides>
   ========================================================================== */

.<base> { ... }
.<base>-<variant>, .<base>--<modifier> { ... }
.<base> .<descendant> { ... }

/* ── Responsive ───────────────────────────────────────────── */
@media (max-width: 980px) { ... }
@media (max-width: 720px) { ... }
```

Якщо у компонента немає responsive-змін, секцію `── Responsive ──` пропусти повністю.

## Жорсткі правила (не забувай)

- Тільки токени. Жодного хардкоду кольорів, розмірів, тіней, радіусів, шрифтів.
- Якщо потрібного токена нема в `tokens.css`, додай його **перед** використанням.
- Компонент не лізе в селектори інших компонентів.
- Не повторюй типографні стилі вручну. Використовуй `--fs-*`, `--fw-*`, `--ls-*`, `--lh-*` змінні.
- Перед фінальним результатом перевір `docs/anti-slop.md` що ти не зробив один із 30+ AI-патернів (тонкий акцент-бордер, glassmorphism, icon-tile-above-heading, identical-cards-grid тощо).
