# Інструкції для Claude Code

Цей файл Claude Code підвантажує автоматично в кожну сесію. Тут зібрані всі правила, яких треба дотримуватись при роботі над цим проектом.

## Стек

Ванільний HTML + CSS + JS. Без білдера, без npm, без фреймворку. Локальний превʼю: `python3 -m http.server 8000` із кореня проекту.

## Архітектура (коротко)

- `assets/css/tokens.css` — єдине джерело правди для всіх візуальних значень. Кольори, розміри, тіні, радіуси, шрифти. **Жодного хардкоду в компонентах.**
- `assets/css/base.css` — reset, дефолти типографіки.
- `assets/css/layout.css` — `.container`, `section.block`, `.block-head/.block-foot`.
- `assets/css/components/<name>.css` — один компонент на файл. Самодостатній, без залежностей від інших компонентів.
- `assets/js/main.js` — один файл, секції пронумеровані.

Порядок завантаження CSS у `<head>`: `tokens → base → layout → components/*`. Якщо додаєш новий компонент: створи файл, додай `<link>` поруч із сусідами в `<head>`.

## Жорсткі правила (не порушувати)

1. **Жодних хардкод-кольорів.** Кожен `color`, `background`, `border-color`, `box-shadow`, `fill` посилається на токен. Якщо потрібного значення немає в `tokens.css`, додай його **перед** використанням.
2. **Жодних хардкод-розмірів / ваг / spacing.** Усе через `--fs-*`, `--fw-*`, `--ls-*`, `--lh-*`, `--space-*`.
3. **Жодних хардкод-радіусів і тіней.** Тільки `--radius-*` і `--shadow-*`.
4. **Один компонент = один файл.** Компонент не лізе в селектори іншого компонента. Cross-component layout живе в `layout.css`.
5. **Markup це контракт.** Імена класів, які компонент чекає (`.card .photo`, `.live-card .text .big`), це його публічний API. Не перейменовувати без оновлення консьюмерів.
6. **Один H1 на сторінку.** Hero / page header. Не пропускати рівні (h1 → h3 без h2).
7. **Два брейкпоінти, крапка.** 980 (планшет) і 720 (мобайл). Більше не додавати.

## Anti-slop правила (читай перед будь-якою візуальною роботою)

Повний список у `docs/anti-slop.md`. Найважливіше:

- **Не** робити: тонкий акцентний бордер на rounded card (бічна полоска), глассморфізм як декорація, фіолетово-цианові градієнти, gradient-text на заголовках, all-caps body, hero "великий метрик + 3 стати", сітка з 3-4 ідентичних карток, анімація `width/height/padding`, кожна кнопка primary, `display: none` для фіч на мобайлі.
- **Не** використовувати тільки Inter / Roboto / Geist / Plus Jakarta Sans / Space Grotesk без контрастного display-фейсу. Це overused. Підбери інший або спар із display-шрифтом.
- **Не** робити дизайн "для демки v0.dev". Якщо вибір виглядає як перший варіант, який видав би LLM, обери другий.

Гут-чек перед шипом: я роблю **вибір** тут, чи дефолчу? Дефолт = слоп.

## Mobile (≤720px)

Повний плейбук у `docs/responsive.md`. Найважливіше:

- Бічний gutter 16px глобально через `.container`. Окремі секції не задають свій горизонтальний padding.
- Section vertical padding ≈ половина: block 88→56, hero 180→88.
- H1 48 → 30, H2 38 → 24, body не нижче 14.
- Multi-column → single column (`grid-template-columns: 1fr`).
- CTA-кнопки full-width стек.
- Не ховати критичні фічі на мобайлі. Адаптувати, не різати.
- Reset `text-align` всередині nested cards (hero-center не має ліковати у body-картки).
- Floating overlays (hiw-pop, badges) тискаються всередину контейнера.

## Типографіка

Повний список у `docs/type-system.md`.

- Ваги тільки 400 / 500 / 600 / 700 / 800. Ніяких 300 / 900 / italic.
- Tracking слідує розміру: ≥28px → -0.02em; 16-22px → -0.01em або none; uppercase labels → +0.04 / 0.08 / 0.12.
- Display numbers (метрики ≥24px) завжди 800 + tight tracking.
- Uppercase тільки для labels (kicker, badge, footer-label). Не для заголовків і не для body.

## Копірайт (в текстах сайту)

- **Без em-dash (—).** Це AI-маркер. Заміняй на крапку, кому, двокрапку, дужки.
- Без AI-фраз: "dive deep", "leverage", "unleash", "elevate", "seamlessly", "in today's fast-paced world".
- Заголовки не повторюють kicker. Body не повторює заголовок. Кожен текстовий блок заробляє своє місце.

Повний список у `docs/copy-rules.md`.

## Слеш-команди в цьому проекті

- `/component <name>` — створити новий компонент за конвенцією
- `/hero` — згенерувати hero-секцію без слопу
- `/audit-slop` — переглянути поточний код на anti-slop патерни
- `/mobile-check` — пройтись чеклістом мобільної адаптації
- `/new-token <name> <value>` — додати новий design token

## Робочий цикл

1. Запусти превʼю: `python3 -m http.server 8000` із кореня проекту.
2. Перед будь-якою візуальною зміною заглянь у `docs/anti-slop.md`.
3. Перш ніж писати CSS, перевір чи є потрібний токен. Якщо ні, додай.
4. Тестуй на 1280, 980, 820, 720, 390, 360.
5. Перед завершенням: відкрий `docs/responsive.md` чеклист мобайла, пройдися.

## Що робити при невпевненості

Якщо не зрозуміло, як назвати клас, який токен взяти, чи варто це робити окремим компонентом: глянь у `assets/css/components/*.css` за прикладами вже існуючих рішень. Конвенція > винахідливість.
