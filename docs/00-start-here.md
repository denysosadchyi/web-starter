# Старт. Прочитай перш ніж щось чіпати

Цей документ для дизайнера, який вперше відкрив цей репо і хоче зробити сайт за допомогою Claude Code (або іншого AI-кодінг-інструмента) без того, щоб згенерувати типовий AI-слоп.

Якщо ти дев і сам пишеш код, можеш переходити до `architecture.md`. Цей файл для тих, хто планує **просити модель писати код**.

## Що ти отримуєш

Готовий каркас сайту: HTML + CSS + JS, без білдера, без npm. Із продуманою системою design-токенів, mobile-адаптацією, anti-slop правилами і слеш-командами для Claude Code, які примушують модель не дефолтити.

## Перші 30 хвилин

### 1. Скопіюй starter у новий проект

```bash
git clone https://github.com/denysosadchyi/web-starter.git my-new-site
cd my-new-site
rm -rf .git
git init
```

Тепер `my-new-site/starter/` це твій робочий каркас. (Можеш просто перейменувати: `mv starter src` або забрати верхній рівень — як зручніше.)

### 2. Запусти локальний превʼю

```bash
cd starter
python3 -m http.server 8000
```

Відкрий `http://localhost:8000`. Має працювати "з коробки".

### 3. Заміни плейсхолдери в `tokens.css`

Відкрий `starter/assets/css/tokens.css`. Замінити треба дві речі:

**Шрифт** (рядок `--font-base`):
- За замовчуванням стоїть `system-ui` (нейтральний дефолт без локу).
- Якщо знаєш, який шрифт використовуєш, постав його. Якщо ні, **залиш system-ui** до моменту, коли визначишся з брендом.
- Не клади Inter / Roboto / Plus Jakarta як єдину family. Це AI-маркер. Якщо береш одну з них, спарь із контрастним display-фейсом (див. `type-system.md`).

**Брендовий колір** (рядок `--brand` і `--brand-rgb`):
- За замовчуванням стоїть синій `#2563eb` як плейсхолдер.
- Заміни на колір клієнтського бренду. **Обов'язково** оновлюй обидва: hex і rgb-fragment.
- Похідні кольори (`--brand-ink`, `--brand-soft`, `--shadow-brand`) автоматично перерахуються? Ні, їх теж заміни вручну. RGB-fragment використовується в shadow-rgba, тому достатньо змінити hex + rgb + ink + soft.

### 4. Прочитай anti-slop

Відкрий `docs/anti-slop.md`. Прочитай хоча б один раз. Це список патернів, які роблять дизайн "AI-generated на дивані за 5 хвилин". Завдання — їх не виробляти.

Не вчи список напамʼять. Твоє завдання — мати його в голові на момент, коли просиш Claude щось згенерувати, щоб перевірити, чи нема в результаті якогось із цих патернів.

### 5. Перевір що CLAUDE.md працює

Запусти Claude Code в папці проекту:

```bash
claude
```

Спитай щось типу: "які жорсткі правила цього проекту?". Claude має відповісти посиланнями на правила з `CLAUDE.md` (tokens-first, two breakpoints, anti-slop). Якщо відповідь розлога і загальна — значить `CLAUDE.md` не підвантажений. Перевір що ти запустив `claude` з тієї папки, де лежить `CLAUDE.md`.

## Як просити Claude писати код, щоб не було слопу

### Використовуй слеш-команди

Замість "зроби мені hero", напиши `/hero <короткий опис проекту>`. Команда автоматично підвантажить anti-slop правила, конвенцію компонентів, mobile-адаптацію.

Доступні команди в цьому проекті:

- `/component <name>` — створити новий CSS-компонент за конвенцією
- `/hero <опис>` — згенерувати hero без AI-слопу
- `/audit-slop` — переглянути поточний код на anti-slop патерни
- `/mobile-check` — пройтись чеклістом мобільної адаптації
- `/new-token <ім'я> <значення>` — додати новий design token

Команди живуть у `starter/.claude/commands/`. Якщо хочеш свою — створи там новий `.md` файл за тим же шаблоном.

### Якщо команди немає, дай Claude конкретний контекст

Поганий промпт:

> "Зроби красиву секцію з підпискою на розсилку"

Що отримаєш: input із градієнтом, glassmorphism-картка, центрований text, два primary buttons. Слоп.

Хороший промпт:

> "Додай секцію з підпискою на email. Один input + одна primary-кнопка в горизонтальному рядку (на мобайлі стек full-width). Без glassmorphism, без градієнтів. Використай тільки існуючі токени. Поклади CSS у `assets/css/components/email-subscribe.css` за конвенцією компонента (див. існуючі файли)."

Що отримаєш: чистий компонент за конвенцією. Без слопу.

### Покажи Claude приклад

Якщо є компонент, який тобі вже подобається, покажи на нього: "зроби нову секцію в стилі `assets/css/components/header.css` — структура, naming, mobile-адаптація мають бути аналогічні". Це працює краще ніж "зроби красиво".

## Чого не варто просити Claude

- "Зроби сайт схожий на [Stripe / Linear / Vercel]" → ти отримаєш дешеву копію без характеру. Опиши **функціональність**, а характер додавай через токени і анти-слоп.
- "Додай анімацій щоб було живо" → отримаєш bouncy-easing, animated-width, parallax. Анімаціями керуй точково: "плавний fade на появі при скролі через `IntersectionObserver`, transform/opacity, no bounce".
- "Зроби responsive" → це й так у конвенції. Якщо щось не працює на мобайлі, скажи конкретно: "на 720 перевір що CTA full-width і нема горизонтального скролу".

## Якщо щось пішло не так

- **Шрифт виглядає не так як на референсі** → переконайся що додав `<link>` на Google Fonts (або self-host) у `<head>` *перед* `tokens.css`.
- **CSS-зміни не підтягуються** → hard-reload браузера (`Ctrl/Cmd + Shift + R`) або додай query-string до `<link>`: `tokens.css?v=2`.
- **На мобайлі горизонтальний скрол** → НЕ став `overflow-x: hidden` на body. Знайди дитину що оверфлоує (зазвичай це elem із `width: 110%` або negative margin без mobile-reset) і виправ її.
- **Claude генерить код, який ігнорує токени** → нагадай прямим повідомленням: "перевір `docs/architecture.md`, hard rule #1: жодних хардкод-кольорів. Перепиши через токени."

## Деплой

Коли сайт готовий, варіанти:

- **GitHub Pages**: запушити в репо, увімкнути Pages у Settings → Pages → branch `main`, folder `/starter` (якщо не виносив наверх). Деплой автоматичний.
- **Netlify**: drag-and-drop папку `starter/` на netlify.com або підключити репо. У `templates/netlify.toml` є готовий конфіг — скопіюй у корінь.
- **Vercel**: те саме що Netlify. У `templates/vercel.json` є готовий конфіг.

Деталі в `preview.md`.
